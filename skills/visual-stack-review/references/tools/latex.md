# LaTeX / XeLaTeX / LuaLaTeX — Deep Dive

**Variants:** pdfLaTeX, XeLaTeX, LuaLaTeX (all compile `.tex` → PDF)  
**License:** Free (TeX Live distribution, MIT/LPPL)  
**Language:** LaTeX markup (own DSL); Lua scripting for LuaLaTeX  
**Install:** TeX Live (Linux/Mac), MiKTeX (Windows), or `brew install --cask mactex`  
**Ecosystem age:** ~45 years (TeX: 1978, LaTeX: 1984)

---

## The three variants — which one matters when

**pdfLaTeX** — the oldest, fastest, most compatible. Limited to 8-bit fonts (no Unicode support without workarounds). Still the default for many academic journals. If the document uses English-only text and standard fonts (Times, Helvetica, Palatino), pdfLaTeX works fine.

**XeLaTeX** — adds Unicode support and the ability to use any system font via `fontspec`. This is the modern choice for documents using custom brand fonts, non-Latin scripts, or OpenType features (ligatures, small caps, old-style numerals). Slower than pdfLaTeX.

**LuaLaTeX** — XeLaTeX's capabilities plus Lua scripting embedded in the document. Useful for programmatically generated content (loop over a data structure to produce table rows). Slowest compile, most flexible.

**For most new document work: default to XeLaTeX.** Unicode support and modern font handling are worth the compile speed cost.

---

## Quality ceiling for designed documents

**Honest ceiling:** LaTeX's text typesetting quality is the highest achievable from any tool — better line breaking than CSS engines, superior widow/orphan control, professional-grade hyphenation in every language, correct optical margin adjustment. For books, academic papers, and long-form technical documents, LaTeX output is the gold standard.

The ceiling is hit immediately for:
- Visual design (multi-column, brand-heavy, image-dominant layouts)
- Iterative authoring by non-LaTeX users
- Web (HTML) output from the same source
- Documents where the designer needs visual control

## What LaTeX is genuinely good at

**Text typesetting quality.** LaTeX's line-breaking algorithm (Knuth-Plass) is still unmatched. It considers the entire paragraph when placing line breaks, not just individual lines. The result is paragraphs with consistent visual texture — no awkward gaps, no stretched lines. Every CSS-based tool uses a greedy line-breaking algorithm that produces noticeably inferior text colour.

**Widow and orphan control.** `\widowpenalty`, `\clubpenalty`, and related parameters give precise control over widows and orphans. LaTeX respects these reliably. CSS tools treat them as suggestions.

**Mathematical typesetting.** The reference standard for mathematical notation. Every other tool's math is judged against LaTeX's output. If the document contains equations, LaTeX is the default choice unless there's a strong reason not to use it.

**Cross-references and citations.** `\label{}` / `\ref{}` / `\pageref{}` for cross-references, BibTeX/BibLaTeX for citations — both work correctly and automatically update when content changes. A TOC generated by LaTeX is always accurate because it's generated from the document structure, not typed manually.

**Long-form stability.** A 400-page LaTeX document is as stable as a 10-page one. CSS-based tools often degrade in predictability past ~50 pages because of cumulative layout effects.

**Footnotes.** True typeset footnotes that fit the page correctly, balance across columns if needed, and work with floating elements. No other tool matches LaTeX footnote handling.

**Hyphenation.** Language-aware hyphenation using the `babel`/`polyglossia` packages. Correct hyphenation for French, German, Arabic, etc. — not just English guessing.

**CTAN packages.** 45 years of packages. Whatever you need, someone has probably built it. `longtable` for multi-page tables, `pgfplots` for publication-quality charts, `tikz` for precise diagrams, `glossaries` for terminology, `nomencl` for notation lists.

## Where LaTeX loses to every alternative

**The authoring experience.** LaTeX source files are not readable by humans who don't know LaTeX. A table in LaTeX looks like this:
```latex
\begin{tabular}{|l|r|r|}
\hline
Item & Qty & Price \\
\hline
Widget & 3 & \$12.50 \\
\hline
\end{tabular}
```
Compare to HTML. For designers or non-technical authors, this is a hard barrier.

**Iteration speed.** A medium-complexity LaTeX document compiles in 10-30 seconds. A document using cross-references and bibliography requires 3-4 compile passes (pdflatex → bibtex → pdflatex → pdflatex). With BibLaTeX and `latexmk`, this is automated, but it's still slow compared to Typst (1-2 seconds) or browser-based tools (instant preview).

**Error messages.** LaTeX error messages are notoriously incomprehensible. A missing `}` can produce 40 lines of error output that don't point to the actual problem. The LaTeX debugging experience is a significant time cost.

**Visual layout control.** LaTeX is a text typesetter, not a page layout tool. Complex multi-column layouts, absolute positioning, overlapping elements, and brand-specific design are difficult and often impossible without deep package knowledge. InDesign or even HTML+CSS is far more capable for design-heavy documents.

**No web output (practically).** LaTeX4ht and Pandoc can convert LaTeX to HTML, but the output often requires significant cleanup. LaTeX is a one-way tool to PDF.

**Images and figures.** LaTeX's figure placement (`htbp` floats) is powerful but often surprising — LaTeX decides where to place figures, and overriding it requires package hacks. For documents where images must appear exactly where authored, LaTeX's approach is frustrating.

## The three modern LaTeX approaches

**Pure LaTeX** — write `.tex` directly. Maximum control, maximum learning curve. Right for academic papers, books, and technical documentation where the author knows LaTeX.

**LaTeX via Pandoc** — write Markdown or other formats, use Pandoc to convert to LaTeX for compilation. Separates content from LaTeX typesetting. Good for teams where only the pipeline owner knows LaTeX. See `references/tools/pandoc.md`.

**LaTeX via R Markdown / Quarto** — write in R Markdown or Quarto (`.qmd`), which compiles to LaTeX then PDF. The standard for academic documents with embedded statistical analysis. Knitr/Jupyter execute code blocks inline; output integrates into the document automatically.

## Common pain points and fixes

**`Package xyz not found`**  
Install missing packages: `tlmgr install xyz` (TeX Live). On MiKTeX, packages install on demand.

**Figures not where I put them**  
LaTeX floats by design. Use `\FloatBarrier` from the `placeins` package, or `[H]` placement from the `float` package to force exact placement. Warning: `[H]` can cause awkward whitespace.

**Bibliography not updating**  
Run the full compile sequence: `pdflatex → bibtex → pdflatex → pdflatex`. Or use `latexmk -pdf -bibtex` to automate.

**Font not working**  
For XeLaTeX: confirm the font is installed on the system (`fc-list | grep "Font Name"`). Use `\setmainfont{Font Name}` in the preamble. For LuaLaTeX: same approach, also works.

**Table too wide for page**  
Use `tabularx` package with `X` column type (expands to fill available width), or `longtable` for multi-page tables with `p{Ncm}` fixed-width columns.

## Migration cost: from HTML+CSS (any tool) to LaTeX

**Effort: Very High** — this is a paradigm shift, not a migration.

**What changes:**
- All content rewritten in LaTeX markup
- All styling reimplemented in LaTeX packages and commands (no CSS)
- Build pipeline: any tool → TeX Live compiler + latexmk
- Anyone who authors must learn LaTeX

**What you keep:**
- Content (can be converted from HTML via Pandoc, with manual cleanup)
- Design intent (must be re-implemented in LaTeX commands)

**When this migration is worth it:**
- Long-form academic or technical documents that will be produced repeatedly
- Mathematical content is a primary requirement
- Text typesetting quality is more important than visual design flexibility
- The author(s) are willing to learn LaTeX

**When it is not worth it:**
- Brand-heavy or design-heavy documents
- Non-technical authors
- Web output is also needed
- Short or one-off documents

---

## Migration cost: from LaTeX to Typst

**Effort: Medium** — same paradigm (markup DSL → PDF), different language.

Typst is the natural successor for LaTeX users who want faster compilation, better error messages, and more predictable layout. The content can often be converted semi-automatically. Math syntax is similar but not identical. See `references/tools/typst.md`.

---

## When to choose LaTeX

- Academic papers, theses, dissertations (often required by journals/universities)
- Books with extensive cross-references, footnotes, bibliographies
- Mathematical or scientific documents
- Long-form technical documentation (manuals, standards)
- The author knows LaTeX or is willing to learn
- Text typesetting quality is the primary constraint
- Print-quality output with correct hyphenation across multiple languages
